# Achievement evidence and profile highlights

Last reviewed: 2026-09-15. GitHub's [profile reference](https://docs.github.com/en/account-and-profile/reference/profile-reference) describes achievements as a public-preview feature. The numerical milestones below are [community-maintained observations](https://github.com/Schweinepriester/github-profile-achievements), not a contractual API specification.

| Achievement | Observed milestones | Evidence to retain |
| --- | --- | --- |
| Pull Shark | 2 / 16 / 128 / 1024 authored PRs merged | PR author, merged state, URL |
| Pair Extraordinaire | 1 / 10 / 24 / 48 merged PRs containing coauthored commits | Actual coauthors, commit and PR URLs, one count per PR |
| Galaxy Brain | 2 / 8 / 16 / 32 accepted answers | Chosen answer and its author, discussion URL |
| Starstruck | 16 / 128 / 512 / 4096 stars on a repository the user created | One repository, creator evidence, current stars |
| Quickdraw | Closing an issue or PR within five minutes | Original and closure timestamps |
| YOLO | Merging one's own PR without code review | PR and actual review history |
| Public Sponsor | Publicly sponsoring open-source work via GitHub Sponsors | Sponsorship visibility and profile observation |

Do not infer awards solely from these counts. GitHub may process activity asynchronously, visibility may differ, and the full eligibility rules are not public. Never change branch protections, forge coauthors, or manufacture engagement to meet a target.

The official `community/community` Discussions no longer award achievements, as explained in the [GitHub announcement](https://github.com/orgs/community/discussions/106536). Project Discussions elsewhere may qualify. Answering a question does not guarantee that its author or a maintainer will accept it.

Arctic Code Vault and Mars 2020 were historical events. Community records list Heart On Your Sleeve, Open Sourcerer, and internal GitHub achievements as unavailable for normal participation; they are not actionable targets in gh-pro.

## Highlights are different

The [official profile reference](https://docs.github.com/en/account-and-profile/reference/profile-reference) lists PRO, Developer Program Member, Security Bug Bounty Hunter, GitHub Campus Expert, and Security advisory credit. These reflect subscriptions, program membership, or accepted work; adding a README image cannot create them.

An evidence-supported correction to an already-public advisory is a useful contribution route. Follow the [Advisory Database contribution guidelines](https://github.com/github/advisory-database/blob/main/CONTRIBUTING.md): one advisory per PR, public supporting sources, and no undisclosed vulnerabilities or exploit code. Submit through the [official improvement process](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/fix-reported-vulnerabilities/edit-advisory-database), and let the curation team determine acceptance and credit. Improving a reference is not a claim of discovering the vulnerability.
